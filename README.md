# 공지사항 알리미 (doduck.co.kr)

도덕파크타운 홈페이지에 새 공지가 올라오면 **카카오톡(나에게 보내기)** 과 **텔레그램**으로 알려줍니다.
GitHub Actions에서 5분마다 자동 실행되며, 서버가 필요 없고 비용도 들지 않습니다.

## 동작 방식

```
5분마다 (GitHub Actions)
  │
  ├─ 메인 페이지에서 공지 목록 수집        ← 로그인 불필요
  ├─ 이미 본 글번호와 대조해 신규만 추출
  ├─ 신규가 있으면 로그인 후 본문 취득     ← 로그인 필요
  ├─ 카카오톡 + 텔레그램 발송
  └─ 확인한 글번호를 state/seen.json에 커밋
```

신규 판별은 **글번호**(9767, 9766 …)로 합니다. 이 사이트는 게시판 전체가 하나의 증가하는
번호를 공유하므로, 글이 수정되거나 순서가 바뀌어도 오작동하지 않습니다.

## 알아둘 제약

| 항목 | 내용 |
|---|---|
| 카카오 수신자 | **본인 1명만**입니다. 개인 자격으로는 단체방 자동 발송이 불가능합니다 (알림톡은 사업자등록 필요) |
| 카카오 글자수 | 기본 텍스트 템플릿은 **200자 제한**이라 본문이 잘리거나 아예 생략됩니다. 링크는 항상 온전히 보존합니다. 전문은 텔레그램으로 옵니다 |
| 카카오 링크 | "공지 보기" 버튼(`link.web_url`)이 개인 앱에서 등록 도메인 루트로 치환되는 사례가 있어, 실제 목적지 URL을 텍스트 안에도 그대로 노출합니다(자동 링크 처리됨) |
| 링크 열람 | 공지 상세는 로그인이 필요해, 링크를 눌러도 로그인 후에만 보입니다 |
| 실행 지연 | GitHub Actions cron은 정시를 보장하지 않아, 실제로는 몇 분 늦게 실행될 수 있습니다 |
| 이미지 발송 | 텔레그램(개인·채널)에만 첨부됩니다. 카카오는 텍스트 템플릿만 지원해 이미지를 담지 못합니다 |
| 밴드 사진 | 밴드 Open API는 글 작성 시 텍스트만 지원합니다. 사진은 밴드 글에 첨부되지 않고 링크 안내로 대체됩니다 |
| 본문 없음 | 이 사이트는 이미지만 첨부하고 텍스트가 없는 공지가 많습니다. 이런 글은 "(본문 내용은 없습니다.)"로 표시되며, 이는 정상입니다 (취득 자체가 실패한 경우와는 다른 문구로 구분됩니다) |

입주민에게는 **네이버 밴드**(주채널, 새 글 푸시 알림)와 텔레그램 채널(보조)로 발행됩니다.
밴드 API는 사진 첨부가 불가능해 제목·본문·링크로 발행하고 사진은 링크에서 보도록 안내합니다.
밴드/채널 초대 링크는 검수된 인원에게만 공유하는 전제입니다.

## 최초 설정

### 1. 텔레그램 봇 (5분, 무료)

1. 텔레그램에서 `@BotFather` 검색 → `/newbot` → 이름 입력 → **토큰** 받기
2. 만들어진 봇과 대화를 시작해 아무 메시지나 한 번 보내기
3. chat_id 확인:
   ```bash
   TELEGRAM_BOT_TOKEN=<토큰> npm run telegram-chatid
   ```

### 2. 카카오 "나에게 보내기"

1. [카카오 개발자센터](https://developers.kakao.com)에서 앱 생성
2. **앱 설정 → 플랫폼 → Web**에 사이트 도메인 등록: `http://www.doduck.co.kr`
3. **카카오 로그인** 활성화 ON, Redirect URI에 `https://localhost` 등록
4. **동의항목 → 카카오톡 메시지 전송(`talk_message`)** 을 사용 설정
5. `앱 키 → REST API 키`를 복사한 뒤 refresh_token 발급:
   ```bash
   export KAKAO_REST_API_KEY=<REST API 키>
   npm run kakao-token                 # 출력된 주소를 브라우저에서 열고 동의
   npm run kakao-token -- <code>       # 리다이렉트 주소의 code= 값
   ```
6. 출력된 `KAKAO_REFRESH_TOKEN`을 보관

> ⚠️ `refresh_token`은 약 2개월마다 만료됩니다. 만료가 가까워지면 시스템이 새 값을
> 알림으로 보내주므로, 그때 Secrets를 교체하면 됩니다. **이 알림을 놓치면 조용히 멈춥니다.**

### 3. GitHub Secrets 등록

저장소 → Settings → Secrets and variables → Actions

| 이름 | 설명 |
|---|---|
| `SITE_ID` | 홈페이지 아이디 |
| `SITE_PW` | 홈페이지 비밀번호 |
| `KAKAO_REST_API_KEY` | 카카오 REST API 키 |
| `KAKAO_REFRESH_TOKEN` | 위에서 발급받은 값 |
| `KAKAO_CLIENT_SECRET` | (선택) 사용 설정한 경우만 |
| `TELEGRAM_BOT_TOKEN` | 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 위에서 확인한 값 (본인 수신용) |
| `TELEGRAM_CHANNEL_ID` | (선택) 입주민 구독용 채널 ID |
| `TELEGRAM_ADMIN_BOT_TOKEN` | (선택) 시스템 경보 전용 봇 토큰 |
| `TELEGRAM_ADMIN_CHAT_ID` | (선택) 그 봇에서 확인한 본인 chat_id |
| `BAND_ACCESS_TOKEN` | (선택) 네이버 밴드 개발자센터에서 발급한 토큰 |
| `BAND_KEY` | (선택) 발행할 밴드의 band_key (`band-diag`로 확인) |
| `ALLPOSTS_BOT_TOKEN` | (선택) "전체 게시글" 감시봇 토큰 |
| `ALLPOSTS_CHAT_ID` | (선택) 그 봇에서 확인한 수신 chat_id |
| `ALLPOSTS_CHANNEL_ID` | (선택) 그 봇의 구독용 채널 ID |

### 3-1. (선택) 입주민 구독용 텔레그램 채널

입주민이 각자 구독해서 알림을 받게 하려면 텔레그램 **채널**을 만듭니다. 무료이고 구독자 수 제한이 없습니다.

1. 텔레그램 → 메뉴 → **새 채널(New Channel)** 생성
2. 공개/비공개 선택 — **비공개(Private) 권장** (초대 링크를 아는 사람만 입장)
3. 채널 → 관리 → **관리자(Administrators) → 관리자 추가**로 **우리 봇을 추가**하고 **게시(Post Messages) 권한**을 부여
4. 채널 ID 확인: 채널에 아무 메시지나 하나 올린 뒤
   ```bash
   TELEGRAM_BOT_TOKEN=<토큰> npm run telegram-chatid
   ```
   `-100`으로 시작하는 숫자가 채널 ID입니다
5. 그 값을 `TELEGRAM_CHANNEL_ID` Secret으로 등록
6. 채널 **초대 링크**를 카카오 오픈채팅방에 한 번 공지 → 입주민이 각자 구독

> 채널에는 **제목·본문·첨부 이미지**가 그대로 발행됩니다(`config.js`의
> `notify.telegram.channel.includeBody: true`). 공지 본문은 홈페이지 로그인이 필요한
> 회원 전용 내용이라, **채널 초대 링크는 검수된 인원에게만 공유**하는 것을 전제로 합니다.
> 불특정 다수에게 링크가 퍼질 가능성이 있다면 `includeBody`를 `false`로 되돌려
> 제목·링크만 발행하도록 바꾸세요.

### 3-2. (선택) 시스템 경보 전용 텔레그램 봇

로그인 실패·사이트 오류·하트비트 같은 **운영 경보**는 공지 알림("도파타 알리미")과
완전히 다른 성격의 메시지입니다. 같은 봇으로 섞어 받으면 "새 공지인가, 오류인가"를
매번 열어봐야 구분되니, 관리자만 보는 별도 봇으로 분리합니다.

1. `@BotFather`에서 두 번째 봇 생성 (예: `도파타 관리봇`) → 토큰 받기
2. 그 봇과 대화 시작해 아무 메시지나 한 번 보내기
3. chat_id 확인 — Actions 탭에서 mode를 **`admin-bot-diag`**로 실행하거나, 로컬에서:
   ```bash
   TELEGRAM_BOT_TOKEN=<두 번째 봇 토큰> npm run telegram-chatid
   ```
4. 토큰은 `TELEGRAM_ADMIN_BOT_TOKEN`, chat_id는 `TELEGRAM_ADMIN_CHAT_ID` Secret으로 등록

> 이 둘을 등록하지 않으면 경보는 기존처럼 공지 알림 봇으로 자동 전송됩니다(끊기지 않음).
> 나중에 언제든 추가할 수 있습니다.

### 3-3. 입주민 주채널 — 네이버 밴드

텔레그램은 입주민에게 생소하므로, 아파트 커뮤니티에서 가장 익숙한 **네이버 밴드**에
새 공지를 자동으로 올리고 멤버에게 푸시 알림을 보냅니다. 무료이고 가입은 전화번호/네이버/카카오
계정으로 1분이면 됩니다.

1. 밴드 앱에서 **밴드 만들기** (예: `도덕파크타운 공지사항`, 비공개 권장)
2. [밴드 개발자센터](https://developers.band.us) → **My Apps → 앱 등록**
   (서비스명·유형만 입력, Redirect URL은 아무 도메인이나 무방 — 사용하지 않음)
3. 등록한 앱에서 **"밴드 계정 연동"** 클릭 → 권한 허용 → 화면에 표시되는 **Access Token** 복사
   (`ZQ`로 시작. 카카오와 달리 code 교환 절차 없음, 유효기간 약 10년)
4. `BAND_ACCESS_TOKEN` Secret 등록 후 Actions에서 mode **`band-diag`** 실행 → 가입한 밴드 목록과 `band_key` 출력
5. 해당 값을 `BAND_KEY` Secret으로 등록
6. 밴드 **초대 링크**를 카카오 오픈채팅에 한 번 공지 → 입주민이 각자 가입

> 밴드 Open API의 글 작성은 `content`(텍스트)만 받습니다. **사진은 첨부되지 않으며**
> 글에 "첨부 사진 N장은 위 링크에서 확인하세요"가 자동으로 붙습니다.
> 토큰이 만료되면(`result_code 10401`) 3단계를 다시 하면 됩니다.

### 3-4. (선택) "전체 게시글" 감시봇 — 공지사항 제외 전 게시판

공지사항 봇은 `[생활지원센터-공지사항]` 게시판만 봅니다. 민원게시판·선거관리위원회·계약서 등
**그 외 모든 게시판**의 새 글을 놓치지 않으려면 별도 봇을 하나 더 둡니다. 로그인이 필요한
전 게시판 통합 "최근게시글" 목록(`page_kind=rpost`)을 읽어, 공지사항만 제외하고 알립니다.

`board-survey` 도구로 실제 활동 중인 게시판 5개(공지사항·민원게시판·선거관리위원회·
자유게시판·계약서)를 전수 검증한 결과, 전부 공지사항과 **동일한 템플릿**을 쓰는 것을
확인했습니다. 그래서 이 봇도 공지사항 봇과 동일하게 **제목·게시판·본문·이미지**를
전부 보냅니다. (새 게시판이 생겨 템플릿이 다르면 자동 폴백 휴리스틱이 대신 동작합니다.)

1. `@BotFather`에서 세 번째 봇 생성 (예: `도파타 전체알림`) → 토큰 받기
2. 그 봇과 대화 시작해 아무 메시지나 한 번 보내기
3. chat_id 확인 — Actions 탭에서 mode를 **`allposts-bot-diag`**로 실행
4. 토큰은 `ALLPOSTS_BOT_TOKEN`, chat_id는 `ALLPOSTS_CHAT_ID` Secret으로 등록
5. (선택) 입주민 채널과 같은 방식으로 채널을 만들어 관리자가 추가하고 `ALLPOSTS_CHANNEL_ID`도 등록하면,
   구독자에게도 함께 발행됩니다

> 어느 게시판을 제외할지는 `config.js`의 `allPosts.excludeBoardLabelIncludes`
> (기본값 `['생활지원센터-공지사항']`)로 조정합니다. 다른 게시판도 더 빼려면
> 배열에 게시판 라벨 문자열(예: `'주민자치회-선거관리위원회'`)을 추가하면 됩니다.

### 4. 첫 실행 (시딩)

Actions 탭 → **공지사항 감시** → Run workflow → mode에 **`seed`** 선택

기존 공지 9건을 "이미 본 것"으로 기록만 하고 발송하지 않습니다.
**이 단계를 건너뛰면 첫 실행에서 기존 글이 한꺼번에 날아옵니다.**
같은 `seed` 실행이 "전체 게시글" 감시봇도 함께 시딩합니다(3-4단계를 설정했다면).

이후부터는 자동으로 주기적으로 돌며, 새 글이 있을 때만 알림이 옵니다.

## 로컬에서 확인하기

```bash
npm install
npm run check              # 목록이 제대로 읽히는지 (알림 안 감)
npm run test-notify        # 카카오/텔레그램에 테스트 메시지 발송
npm run login-test         # 로그인과 본문 취득이 되는지
npm run dry                # 신규 감지 + 메시지 미리보기 (발송 안 함)
```

환경변수는 `.env.example`을 참고해 셸에 export하거나 앞에 붙여 실행하세요.

## 운영 중 받게 되는 경보

시스템은 조용히 죽지 않도록 아래 상황에서 알림을 보냅니다.

- **목록 파싱 0건이 3회 연속** → 사이트 개편으로 셀렉터가 깨졌을 가능성
- **로그인 실패** → 계정/세션 문제. 이때도 제목+링크 알림은 계속 나갑니다
- **카카오 발송 3회 연속 실패** → 토큰 확인 필요
- **refresh_token 갱신됨** → Secrets 교체 필요
- **매일 오전 9시 하트비트** → "정상 동작 중". 이게 안 오면 시스템이 멈춘 것입니다

## 설정 바꾸기

`config.js` 한 파일만 고치면 됩니다.

```js
boards: { include: ['18'] }        // '4'를 추가하면 선거관리위원회 공지도 받습니다
keywords: ['장학금', '승강기']      // 비워두면 전체. 채우면 해당 단어가 든 글만
notify: {
  telegram: { mode: 'always' }     // 'fallback'으로 바꾸면 카카오 실패 시에만 발송
}
detail: {
  includeImages: true,              // false면 이미지 첨부 없이 텍스트만
  maxImages: 6,                     // 글 하나당 첨부 최대 장수
}
heartbeatHourKst: 9                // null이면 하트비트 끔
```

발송 주기는 `.github/workflows/watch.yml`의 `cron` 값으로 조정합니다 (현재 5분마다).

> 저장소가 **Public**이라 GitHub Actions 사용량이 무제한입니다.
> Private으로 되돌리면 무료 한도(월 2,000분)를 넘겨 과금되므로, 그때는 주기를 30분 이상으로 늘려야 합니다.

## 이 사이트를 다루며 넘어야 했던 것들

나중에 문제가 생겼을 때 참고할 기록입니다.

1. **WAF 차단** — 앞단 보안장비가 비브라우저 User-Agent를 `se-cu.com/error.html`로 302시킵니다.
   브라우저 UA를 반드시 보내야 합니다.
2. **규격 위반 헤더** — 서버가 `P3P : CP=...`처럼 헤더 이름과 콜론 사이에 공백을 넣어 보냅니다.
   RFC 7230이 거부하도록 규정한 형태라 Node 내장 `fetch`와 `node:http`가 모두
   `Invalid header token`으로 실패합니다. 그래서 `src/http.js`에 소켓 기반의
   관대한 HTTP 클라이언트를 직접 두었습니다.
3. **EUC-KR** — 페이지도 로그인 폼 전송도 EUC-KR입니다. 변환을 빠뜨리면 한글이 모두 깨집니다.
4. **제목 잘림** — 메인 목록의 제목은 `…이전 안..`처럼 잘려 나옵니다.
   전체 제목은 상세 페이지에서 가져옵니다.

src/
  http.js                 소켓 기반 HTTP 클라이언트 (EUC-KR, 쿠키, 재시도)
  parse.js                메인 페이지 공지 목록 파서 (go_view_hn 인자 파서 포함)

  detail.js               로그인 및 상세 본문 추출
  messages.js             발송 문구 조립 (카카오 예산 계산 등)
  state.js                본 글번호 관리 (경로 지정 가능 — 파이프라인별 분리)
  notify/
    kakao.js              카카오 나에게 보내기
    telegram.js           텔레그램 (개인·채널·관리자봇·전체게시글봇 공용)
    band.js                네이버 밴드 Open API
    index.js               발송 라우팅 및 폴백
  index.js                공지사항 파이프라인 (본문·이미지 포함)
  allposts.js              전체 게시글 파이프라인 (공지사항 제외, 제목만)
tools/                    설정·진단용 스크립트
state/seen.json           공지사항 파이프라인이 확인한 글번호
state/seen-allposts.json  전체 게시글 파이프라인이 확인한 글번호
(둘 다 Actions가 자동 커밋)
